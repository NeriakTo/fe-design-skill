# 資訊看板設計依據 v1.1

## 適用範圍

**適用**：營運型網站平台的資料頁與營運後台（例如能源管理、物業管理、製造執行、知識庫），以及其他資料呈現頁面。
**不適用**：平台介紹、產品說明這類給客戶看一眼的對外頁面，走本文件第五節的另一條路線。
**不含配色**：各平台沿用既有品牌色。本文件規範的是版面結構與元件，不是色票。

## 〇、與既有規範的關係

若專案已有定版的模組級畫面規範（含元件規格、顏色職責、手機版規則），以該規範為準；本依據只在其未涵蓋處補充，兩者衝突時以專案規範為準。沒有專案規範時，直接適用本依據。

專案規範通常已涵蓋本依據的部分條目（例如數字對齊、資料新鮮度的位置、狀態不靠顏色）。遇到這種情況，位置與呈現照專案規範；本依據第二節第 5 項與第三節的走勢線條件，只用於沒有等同規範的專案。

## 一、主線：密度型後台

版面走「一頁看完、當場篩選、當場匯出」的密度型後台，不走留白展示型。

**理由**：使用者是每天要看的營運人員——能源管理看多門市多電號、智慧物業看多社區、製造執行看多機台。留白型版面在同一塊面積裝的資訊少約三成，多對象場景會逼使用者反覆換頁。

**判定方式**：主要清單頁在 1440×900 的視窗裡，不捲動就要看得到 KPI 區、主圖、清單前段三者；清單一頁至少十列。

## 二、五項必備元素

### 1. 數字用等寬字並右對齊
金額、度數、數量、百分比一律等寬字型、右對齊。
**理由**：這些欄位要逐列比大小，直欄對齊時眼睛不用重新對焦。影響可讀性大於配色。
**判定方式**：任一數值欄，相鄰兩列的個位數必須落在同一垂直線上。

### 2. 每個資料頁都要交代資料新鮮度
固定交代四件事：資料來源、更新頻率、時區、頁面或資料版本。
**位置依專案既有規範**——有規範把註記放在頁面頂部的查詢範圍摘要條，或收進狀態條上的展開入口時照辦，不放頁尾；
沒有既有規範的平台放頁尾。版本與來源代碼這類技術識別碼收進技術資訊區，不佔主畫面。
**理由**：同一頁常混不同新鮮度的資料。以能源管理為例，電費帳單是月結、數位電表是 20 秒取樣，沒有這行註記使用者會誤判數字新不新。
**判定方式**：四項缺一即不通過（不論放在頁尾、頂部摘要條或展開入口）。「即時」「最新」這類形容詞不算，要寫得出實際頻率。

### 3. 漲跌與狀態不靠色塊當唯一訊號
顏色只做輔助，形狀、箭頭、文字必須能單獨表意。
若用顏色，只在指標有明確的業務好壞判準時表示好壞（例如超出目標、逾期）；沒有判準時用中性色加文字。不寫死「某指標上升就是壞」：營運規模擴大時，用電或報修件數上升不一定是壞。變化為零、前期為零或無從比較時不上狀態色，寫法見第 5 項。
**理由**：色覺障礙者與黑白列印都讀不到色塊；台灣漲紅跌綠與歐美相反，光看顏色會誤讀；同一個「上升」在不同指標上好壞相反，只看漲跌上色會把好消息標成警示。
**判定方式**：把頁面轉成灰階，所有漲跌與狀態仍要判讀得出來。顏色表好壞時，頁面要寫得出判準（例如「紅色表示超出目標」）；若堅持用漲跌配色當主要訊號，頁面上要明寫配色慣例（例如「漲跌配色依台股慣例」）。

### 4. 清單頁的操作元件下限
清單頁至少要有：期間切換、狀態或分類篩選（各項附筆數）、匯出、分頁。搜尋框視資料量決定。
**理由**：營運人員的動作是「篩出我要的那幾筆，帶走對帳」，缺任一項就要回頭找工程支援。
**判定方式**：四項缺一要在設計文件寫明為什麼不需要，不能默默省略。

### 5. 資料誠實
1. 零就印 0，缺值印破折號；沒資料的區塊保留位置，寫一句現況與下一步，不整塊縮掉。插圖只在不妨礙資訊與操作時使用。
2. 變化值三種情況分開寫，都用中性色、不上狀態色：變化確實為零顯示 0 或 0%；前期為零、本期有數量顯示實際增量並註明「新增」；無從比較顯示破折號。
3. 每個相對數字寫出比較基準（「較上月」「較去年同月」），不只寫「+5」。
4. 同指標、同範圍、同期間、同口徑的數字在畫面出現兩次，要來自同一個值。可加總的指標，合計與小計要和畫面上顯示的組成對得上，並分清本頁小計與全部篩選結果的總計；平均值與比率不適用加總。不同口徑同時出現時，明寫兩者差異。

**理由**：能源帳單、物業費用都要拿去對帳。合計對不上、零被畫成漲跌、比較基準不明，使用者會連整頁都不信。
**判定方式**：抽一張有合計的表，用畫面上顯示的數字重算合計與變化值，對得上才通過；找一個沒資料的區塊，確認位置還在、有一句話。

## 三、建議但非必備

- 主圖下方附一句人話總結（例如「本期累計較前期 +9.8%」），不要只留圖。
- 分類占比用橫條加金額加百分比，底部收一列小計；不用甜甜圈圖表現超過四類的資料。
- KPI 卡不預設每張都畫迷你走勢線。要交代方向，在數值下方的輔助狀態行寫變化與比較基準（例如「較上月 +3.2%」）；要看期間內的走勢，才依卡片空間加走勢線或另放一張圖。專案若有指標卡規範，照該規範。
- 趨勢圖標出高點或事件（如年中慶、換表日），讓異常值有解釋。

## 四、明確不要

- 大圓角與重陰影堆疊。
- 側邊欄放超過三層導覽。
- 動效當主要回饋。營運後台的回饋要即時且明確，不靠動畫傳達狀態。
- 用顏色深淺表示數量級而不標數值。

## 五、對外介紹頁的另一條路線

平台介紹、產品說明、提案簡報這類頁面走克制路線：留白多、每屏一個重點、數字精選不堆疊。不套第一節的密度要求，但第二節的第 3 項（不靠色塊當唯一訊號）仍然適用。

## 六、依據與出處

以無介面瀏覽器實抓公開比較站 `josh.hu/designcompare` 上七種設計 skill 對同一份提示詞產出的儀表板成品，逐張比對得出。

各項元素的來源變體：密度主線取自 ui-ux-pro-max；等寬數字取自 taste-skill；頁尾註記取自 Vercel web-design-guidelines；不靠色塊取自 impeccable；配色慣例明寫取自 Anthropic frontend-design。

v1.1 的第 5 項與第 3 項補充，寫法參考 [Leonxlnx/taste-skill](https://github.com/Leonxlnx/taste-skill)（MIT）的 app-screens 參考文件；該文件的量測數字只當觀察，本文件各條的理由都不靠那些數字。
