# Craft Rule: Taste Layout

> 模組：taste-layout
> 嚴重度：P1（should-fix）
> 引用：`craft.requires: [taste-layout]`
> 來源：Leonxlnx/taste-skill（MIT）gpt-taste v2，摘要改寫
> 適用範圍：**只用於展示型**（品牌頁、活動頁、提案）；混合頁只作用於明列的展示區；實用型（儀表板、後台、企業系統）不載入。簡報屬展示型，但受投影字級、固定畫布與匯出限制，不套本檔的網站區塊間距。本檔的數值與配額都是參考，不是驗收門檻。

## Hero 紀律

### 標題行數鐵律

H1 不得超過 2-3 行。4 行以上是失敗。

修正手段：
- 使用寬容器（`max-w-5xl` / `max-w-6xl` / `w-full`），讓文字水平展開
- 用 clamp 控制字級（`clamp(3rem, 5vw, 5.5rem)`），容器不夠寬就縮字
- 縮減文字量，不要硬擠

### Hero 構圖反預設

「左文右圖」是 AI 最常產出的 Hero 排版，不得作為預設首選。

優先考慮：
- 置中全景（文字居中 + 全幅背景圖 + 深色漸層遮罩）
- 非對稱分割（文字偏左 + 圖片從右下浮入）
- 編輯式分割（左文右圖但大量留白）
- 底部疊圖（文字在下方 40% + 全幅背景）
- 迷你極簡（tiny logo + 短句 + 細 CTA，大量負空間）

只在「左文右圖」確實是最佳選擇時才使用。

### Hero 禁止項

- 不得塞浮動徽章/印章在標題上
- 不得在 Hero 下方放 pill tag 堆
- 不得在 Hero 區放裸數據/統計
- 按鈕文字對比必須清晰（深底白字 / 淺底深字）

## 區塊間距紀律

### 區塊間大量留白

主要區塊之間留出明顯的垂直間距，參考值 `py-32 md:py-48`（或等效值）；短頁、資訊密集的段落可以縮小，依閱讀節奏判斷，不硬套數值。

區塊之間的感覺應該像「獨立的場景」，不是擠在一起的盒子。

### 間距節奏

- 寬鬆與緊湊交替——密集內容區塊後面接寬鬆留白區塊
- 小型區塊仍需足夠周圍空間
- 全頁間距節奏要均勻可控，不要忽大忽小

## Bento Grid 紀律

使用 Bento Grid 時避免非必要的空洞：

- `col-span` / `row-span` 事先算過，盡量嵌合
- `grid-auto-flow: dense` 可以用，但它會讓視覺順序和 DOM 順序不同；用之前確認閱讀順序與鍵盤 Tab 順序仍合理，零空洞不能凌駕閱讀與操作順序
- 3-5 張高意圖卡片優於 8 張草率卡片
- 卡片內容混合大圖、密集排版、CSS 效果

## 構圖多樣性

### 跨區塊錨點變化

長頁可以在下列構圖錨點之間變化（參考，不是配額；短頁或內容一致的頁面用一種也成立）：
- 置中宣言
- 左上引導 + 右下輔助
- 底部疊圖（文字在背景圖下方）
- 左 1/3 文字 + 右 2/3 視覺（經典，不連續使用兩次）
- 右 1/3 文字 + 左 2/3 視覺（反轉經典）
- 離格編輯式偏移

同一錨點連續太多個區塊時，考慮換一種。

### 背景模式變化

背景可以在下列模式之間變化（參考，不是配額；一致的背景也成立）：
- 純色 + 內嵌素材
- 全幅背景圖 + 色調遮罩
- 編輯式側圖（50/50 或 60/40）
- 低飽和的色調漸層（不得是紫藍、藍青這類兩段式「信任感漸層」，見 anti-ai-slop Sin #2）
- 雙色調處理圖片
- 微噪點漸層（高級觸感深度）

同一背景模式連續太多個區塊時，考慮換一種。

## 可選技法（有條件）

- **破格**（文字或圖片跨出容器邊界）：只在窄螢幕不產生水平捲動、文字完整、閱讀順序不受影響時使用，要在 390 寬實測。
- **微噪點材質**：用輕量的 SVG 濾鏡或小圖，不得影響文字辨識，不載入大型圖檔。
- **同心圓角**：內外兩層等距嵌套時，外層圓角＝內層圓角＋間距；不強迫所有容器都圓角化。
- 不採用：滑鼠跟隨光暈、漸層邊框微光（與 anti-slop 的漸層邊框規則與過量 hover 特效規則衝突）。

## 反嵌套盒子紀律

禁止盒中盒中盒排版：
- 不要用巨大圓角容器包住所有東西
- 不要卡片套卡片套卡片
- 不要無理由的儀表板式分隔
- 容器只在有明確用途時使用
- 偏好開放排版、更清晰的留白、更少但更強的容器

## 反微 UI 雜訊

禁止不必要的小型 UI 裝飾：
- 不要無意義的 pill / badge / tag
- 不要假系統標記（「SECTION 01」「QUESTION 05」「00 orchestration layer」）
- 不要裝飾性的程式碼標籤
- 不要假的技術微型文案
- 偏好乾淨標題、更少標籤、真實層次、更清晰的間距
